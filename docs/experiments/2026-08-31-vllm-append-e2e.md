# vLLM 原生与自定义 Append：端到端对照实验

日期：2026-08-31

归档状态：2026-09-02 完成 M0 基线冻结与证据补齐；本次归档操作没有重跑实验、修改历史结果或改变实验结论。

## 1. 结论

在 RTX 4060 8 GiB、Qwen2.5-0.5B-Instruct、vLLM 0.23.0、FP16、FlashAttention、eager、Prefix Caching 关闭的固定配置下，自定义 Append 已经进入真实推理路径，并通过一轮小负载缓存一致性验证。

正式性能实验为 native/custom 各 3 轮，每轮 80 请求，共 480/480 成功。按每轮统计值的中位数比较，自定义组输出吞吐下降 0.79%，TPOT P50 增加 1.61%，TTFT P50 降低 3.32%，E2E P99 增加 5.48%。三对实验的吞吐与 TPOT 变化方向不一致，E2E P99 均升高。

**本组数据未显示稳定的端到端加速；不能写成 TPOT 降低 5%、吞吐提升 4% 等预期收益已经实现。** 这不否定此前 V0–V3 微基准结果，但它们采用不同基线和测量边界，必须分别报告。

## 2. 实验边界与配置

- 模型快照：`7ae557604adf67be50417f59c2c2f167def9a775`。
- 模型服务名称：`Qwen/Qwen2.5-0.5B-Instruct`。
- 服务：vLLM 0.23.0，单 GPU，FP16，`FLASH_ATTN`，`--enforce-eager`。
- 地址：`http://127.0.0.1:8011`。
- 服务参数：max-model-len=2048，gpu-memory-utilization=0.65，max-num-seqs=16，max-num-batched-tokens=2048，block-size=16，seed=20260831，Prefix Caching 关闭。
- 六轮日志中的上述服务参数一致；KV Cache 容量均为 362,784 Token（4.15 GiB 的可用 KV 内存日志）。
- 每轮：新服务进程，先 8 个请求预热，再 80 个请求正式测量；并发 4、输入 1024 Token、输出预算 64 Token、seed=20260831。
- `shared-prefix-ratio` 参数固定为 0.5；本轮没有重新证明输入公共前缀严格等于 50%，也不把它作为消融变量。六批完整的实际输入 Token ID 与输出预算逐项相同。
- 实际顺序：native-r1 → custom-r1 → native-r2 → custom-r2 → native-r3 → custom-r3。
- 预热 48/48 成功，独立保存并排除在正式统计之外。
- 正式实验每轮均 80/80 成功、输出 5120 Token，共 480/480 成功、输出 30,720 Token。

仅替换 FlashAttention decoder 的 Append 更新点。没有替换 Gather，没有验证 BF16、量化 KV、其他注意力后端、CUDA Graph 或多 GPU。自定义实现是适配真实 strides/负槽位/padding 的 Append 适配器，不等同于把原微基准 V3 函数原样接入。

## 3. 接入与正确性证据

注册位置：`FlashAttentionImpl.do_kv_cache_update`，通过独立插件修改当前进程的方法；不修改安装目录中的 vLLM 源文件。

- native：插件直接返回，不安装替换钩子，保留原生方法。
- verify：原生路径写入影子缓存，自定义路径写入实际缓存，同步后按 FP16 原始比特比较。该模式不能用于性能结论。
- custom：只运行自定义 Append；不做影子缓存复制、原生对照或验证同步，仍包含 Python 包装检查及每 256 次调用的审计记录开销。

此前独立适配器测试覆盖默认/非默认 Stream、strided 输入与缓存、padding、负槽位、空输入和奇数形状。12 个 adapter/reference 用例通过，其中 8 个共同支持的用例同时与原生算子比较；4 个边界用例没有调用原生算子，不能视为原生等价验证。

真实请求 verify 实验：4/4 请求成功。主进程审计日志共有 840 条 `verified` 记录；最前面的 24 条来自初始化/探测调用，均为 `mapped_rows=16`、`valid_tokens=0`。排除这 24 条后，真实请求路径包含 816 次 Append 缓存比较、累计 13,728 次有效 Token 写入，0 次缓存比较失败。有效写入计数包含模型各层，不是独立输入 Token 数。

正式 custom 三轮日志各包含 136 条 custom_progress；采样进度的最后调用计数均为 34,816，包含启动、预热和测量，不是正式请求专属计数。三轮插件与适配器哈希一致：

- 插件 SHA256：`2286a1e48114fe3f5faf9aaa3f9b3234ee558544dc14608b05961a8389c5b77f`
- 适配器 SHA256：`ae69dc2c6318f611c344be399da0b3bc0af4f980be5278fb005c38801bdb26cd`

480 个成功响应不等于已经逐项比较生成文本或生成 Token 序列；本报告的缓存一致性结论来自上述 verify 测试，不宣称覆盖所有模型输入。

## 4. 统计口径

- 吞吐采用 JSON 的 `result.wall_output_throughput_tokens_per_second`：成功输出 Token 数除以整轮请求执行墙钟时间，排除输入准备、元数据收集和写盘。
- TTFT、TPOT、E2E 是客户端流式请求统计，不是独立 GPU Prefill/Decode Kernel 时间。
- 主表先分别计算各轮指标，再对三轮指标取中位数；不是把 240 条请求混在一起重新求总体 P50/P99。
- 相对变化 = (custom / native - 1) × 100%。延迟为负表示降低，吞吐为正表示提高。
- 每轮只有 80 个请求，P99 受最慢的少数请求影响；三轮数据不足以提供精确显著性结论。
- 没有进行本次集成路径的瓶颈剖析，因此不能把退化确定归因于某一项 Python 开销、日志写入或 GPU Kernel。
