# 估算性能目标参考（非实测）

## 使用限制

本文只保存项目规划阶段的估算区间和用户希望跟踪的参考数字，不是实验报告，也不是项目已经实现的性能结果。

以下数字不得写成“实测”“达到”或“提升”，不得直接用于 README 结论、简历、面试回答或性能对外宣传。完成控制变量实验后，必须用原始数据重新计算并替换；如果实测低于估算，应保留真实结果。

## 端到端系统参考

固定环境参考：RTX 4060 8 GiB、Qwen2.5-0.5B-Instruct、vLLM 0.23.0。

| 实验 | 估算或旧口径参考 | 正式验收要求 |
| --- | ---: | --- |
| 并发1到并发8的吞吐扩展 | 约7到9倍；旧参考点8.9倍 | 同一 vanilla vLLM、相同请求分布、每档至少5轮 |
| Prefix Cache命中率 | 约70%到85%；旧参考点82% | 同一vLLM版本，仅切换Cache开关，保存服务日志 |
| Prefix Cache对TTFT影响 | 预计降低35%到60%；旧参考点45% | 分别报告P50/P99，不与TPOT混用 |
| Prefix Cache对输出吞吐影响 | 预计提升20%到40%；旧参考点32% | 请求成功率100%，固定并发和输入分布 |

已有工程阶段实测以 `2026-08-10-prefix-cache.md` 为准，不用本表覆盖已有真实数据。

## Kernel逐项消融参考

主形状参考：FP16、`num_kv_heads=2`、`head_dim=64`、`block_size=16`。所有加速比以同一扩展中的朴素CUDA Kernel为1.00倍，不以PyTorch为分母。

| 变体 | Append累计加速估算 | Gather累计加速估算 | 说明 |
| --- | ---: | ---: | --- |
| V0朴素Kernel | 1.00倍 | 1.00倍 | 一个线程负责一个Token并标量循环 |
| V1合并访存 | 1.6到2.0倍 | 1.4到1.8倍 | 相邻线程访问连续Head元素 |
| V2向量化 | 2.0到2.4倍 | 1.7到2.1倍 | 对齐时16字节搬运，尾部标量回退 |
| V3线程布局 | 2.3到2.7倍 | 1.9到2.3倍 | 一个CTA或Warp协作处理一个Token |
| V4其他优化 | 2.4到2.9倍 | 2.0到2.5倍 | 地址计算优化或Qwen主形状特化 |

旧参考点为Append约2.5倍、Gather约2.1倍，位于上述估算区间内，但在逐项消融完成前不视为结果。

## 带宽与端到端参考

- 优化Kernel有效显存带宽暂按130到180 GB/s作为目标观察区间，旧参考点为165 GB/s。
- “约占理论带宽60%”必须先根据本机实际显存频率和位宽计算理论带宽，不能直接沿用。
- 自定义Kernel接入同版本vLLM后，TPOT可能只有3%到10%的变化；旧参考点9%只作为乐观目标。
- 如果没有完成“vanilla vLLM”和“仅替换目标Kernel的同版本vLLM”对照，则端到端Kernel收益统一记为未验证。

## 替换条件

任何估算数字升级为项目结果前，必须同时具备：

1. 完整环境清单和Git commit。
2. 可复制执行的服务与基准命令。
3. 固定并保存的输入分布和随机种子。
4. 未汇总的Kernel样本或逐请求原始时间线。
5. 至少5轮正式重复实验。
6. Kernel与端到端分别汇总，不混用加速比。
