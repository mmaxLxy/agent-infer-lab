# Prefix Cache 长上下文对照实验

日期：2026-08-10

## 1. 实验目标

在相同模型、请求数量、并发度和输出长度下，对比 vLLM 开启与关闭 Prefix Cache 时的端到端性能，并观察共享前缀收益随输入长度变化的趋势。

本实验使用真实本地模型请求，不使用单元测试中的构造时间戳作为性能数据。

## 2. 实验环境

- GPU：NVIDIA GeForce RTX 4060 Laptop GPU，8188 MiB。
- 系统：Windows + WSL2 Ubuntu 24.04。
- CUDA Toolkit：12.9。
- Python：3.12。
- PyTorch：2.11.0+cu129。
- vLLM：0.23.0+cu129。
- 模型：`Qwen/Qwen2.5-0.5B-Instruct`。
- 服务参数：`gpu-memory-utilization=0.60`、`max-model-len=2048`。
- 接口：`/tokenize` 与流式 `/v1/completions`。

## 3. 固定工作负载

每组正式实验使用以下固定参数：

```text
requests: 80
concurrency: 4
input_tokens: 512 / 1024 / 1536
output_tokens: 64
shared_prefix_ratio: 0.75
seed: 20260810
```

Cache 开启组采用干净缓存协议：

1. 每种输入长度开始前重启 vLLM，清空进程内 Prefix Cache。
2. 使用 `seed=20260809`、`shared_prefix_ratio=0.0` 的4个无关请求预热相同输入长度的执行路径。
3. 再运行 `seed=20260810`、共享前缀75%的80个正式请求。
4. 三组正式实验均为80个请求成功、0个请求失败。

该协议避免把重复运行相同 seed 产生的完整 Prompt 命中，错误地计入“75%共享前缀”收益。

## 5. 对照结果

改善比例按以下方式计算：

```text
延迟降低 = (Cache关闭值 - Cache开启值) / Cache关闭值
吞吐提升 = (Cache开启值 - Cache关闭值) / Cache关闭值
```

| 输入长度 | 吞吐提升 | 总耗时降低 | TTFT P50降低 | TTFT P99降低 | E2E P50降低 | E2E P99降低 |
|---:|---:|---:|---:|---:|---:|---:|
| 512 | 11.9% | 10.6% | 55.3% | 40.3% | 10.6% | 8.0% |
| 1024 | 24.3% | 19.5% | 55.9% | 63.9% | 19.0% | 16.2% |
| 1536 | 38.5% | 27.8% | 56.9% | 50.6% | 26.9% | 28.2% |

主要结论：

- 随输入长度由512增长到1536 tokens，输出吞吐收益由11.9%扩大到38.5%。
- E2E P99降幅由8.0%扩大到28.2%，说明长上下文中重复 Prefill 的成本更高。
- TTFT P99降低40.3%至63.9%，符合 Prefix Cache主要减少 Prefill计算的原理。
- TPOT属于逐Token Decode阶段，不应把其单次波动全部归因于Prefix Cache。

## 6. 被排除的数据与原因

- `prefix_cache_on_input1024_2026-08-10.txt`：79/80成功，包含1次 `ConnectionResetError`，不进入正式对照。
- `prefix_cache_on_input512_repeat2_2026-08-10.txt` 与 `prefix_cache_on_input1024_repeat2_2026-08-10.txt`：在同一服务中使用相同seed重复运行，可能命中完整Prompt，只能表示“相同任务重复执行的热缓存上界”。
- 首轮1536 Cache开启结果虽然80/80成功，但正式结论统一采用每档重启、无关预热后的干净实验数据。

## 8. 实验边界

- 每个正式配置当前执行1次，属于工程阶段基准，不是论文级统计。
- WSL2本地服务曾出现偶发连接拒绝或重置，失败感知基准会保留失败类型，不通过自动重试掩盖问题。
- vLLM服务端 `Avg prompt throughput` 和 `Avg generation throughput` 是周期采样快照；正式吞吐、TTFT、TPOT和E2E均采用客户端完整批次统计。
- 当前结论仅适用于本机软硬件、模型和参数组合，不外推为其他GPU或模型的通用结果。

## 9. 可用于项目介绍的结论

> 在RTX 4060 8 GiB上构建Qwen2.5-0.5B真实流式推理基准；在并发4、75%共享前缀下，采用独立服务与无关预热消除完整Prompt缓存污染。输入长度从512增长至1536 tokens时，Prefix Cache使输出吞吐提升11.9%至38.5%，TTFT P99降低40.3%至63.9%，E2E P99降低8.0%至28.2%。
