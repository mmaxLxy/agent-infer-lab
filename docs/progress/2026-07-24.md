# 2026-07-24 阶段工作记录

## 今日目标

建立一套纯 CPU、可独立验证的推理性能指标模块，为后续 vLLM 流式压测和 CUDA 优化提供统一的测量口径。

## 完成内容

### 1. 单请求原始记录与指标

- 新增不可修改的 `RequestTrace`，记录请求编号、开始时间、首 Token 时间、完成时间和输出 Token 数。
- 新增 `RequestMetrics`，统一保存 TTFT、TPOT 和端到端延迟。
- 对请求编号、有限时间、时间先后关系和正整数 Token 数进行输入校验。
- 单 Token 请求没有后续 Token 间隔，因此将 TPOT 明确记为 `None`。

### 2. 批量指标汇总

- 新增不可修改的 `MetricsSummary`。
- 计算请求数量、输出 Token 总数、整批实验持续时间和输出吞吐。
- 使用固定的 nearest-rank 算法计算 TTFT、TPOT 和 E2E 的 P50、P99。
- 拒绝空输入和重复请求编号，避免产生没有统计意义或无法追踪的结果。

### 3. 自动测试

- 覆盖数据不可修改性、TTFT/TPOT/E2E 公式和吞吐公式。
- 覆盖 P50、P99、单 Token、空输入、重复请求编号和非法时间等边界情况。
- 验证相同输入始终得到相同汇总结果。

## 问题与决策

- 问题：首次提交时 WSL 中的 Git 作者身份尚未配置，Git 拒绝创建提交。
- 处理：只在当前仓库配置与既有提交一致的作者身份，避免影响其他项目。
- 决策：本阶段保持纯 CPU，不加入 HTTP、并发调度、GPU、CUDA、Goodput、结果持久化或图表生成。
