## 问题与决策

### Hugging Face 可解析但无法直连

- 问题：WSL 能将 `huggingface.co` 解析为 IP，但 HTTPS 直连超时；Windows WinHTTP 显示直连，与浏览器实际代理配置不一致。
- 根因：浏览器使用 `127.0.0.1:7897` 代理，而命令行未继承该代理。
- 决策：在推理终端显式配置代理环境变量，不修改系统级 WinHTTP 配置。
- 结果：模型下载成功，缓存可复用。

### CUDA Toolkit 完整但 JIT 编译找不到头文件

- 问题：vLLM 已能加载模型，但 FlashInfer JIT 报错 `cuda_runtime.h: No such file or directory`，随后引擎初始化失败。
- 根因：`nvcc` 属于 CUDA 12.9，但 PyTorch 将 `CUDA_HOME` 识别为上一级 `/usr/local`。
- 决策：统一 `CUDA_HOME`、`PATH` 和 `LD_LIBRARY_PATH`，修正工具链来源；不通过重装 CUDA 或禁用 FlashInfer 掩盖路径问题。
- 结果：JIT 编译、模型预热和服务启动全部通过。

### 运行警告的处理边界

- WSL 下 `pin_memory=False` 只影响潜在性能，不影响正确性。
- 首个新输入形状触发 Triton Kernel JIT，造成一次性延迟波动，不视为服务错误。
- Hugging Face 未认证警告只影响下载限额；当前模型已缓存，不阻塞本地推理。
- vLLM 周期日志中的吞吐率混入空闲时间与首次 JIT，不能作为正式性能数据写入简历。
